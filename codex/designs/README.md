# codex/designs/

Architecture designs, proposals, and specs drafted by Codex.

Nothing here is active code. These are design artifacts — proposals for Mike to review
before any implementation is promoted to `core/` or a design track.

## Naming Convention

```
<YYYY-MM-DD>-<track>-<short-slug>.md
```

Examples:
- `2026-03-29-path-d-witness-routing.md`
- `2026-04-01-path-a-async-council.md`
- `2026-04-05-path-b-api-routing.md`

## What a Good Design Doc Contains

- Problem being solved (one sentence)
- Proposed approach
- What changes in core (list of files + nature of change)
- What stays the same
- Risks or open questions
- Suggested validation test

Keep designs under 100 lines. If it needs more, it's probably two designs.
